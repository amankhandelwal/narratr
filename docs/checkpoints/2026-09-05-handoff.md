# Checkpoint — 2026-09-05

**For:** whoever picks this up with no memory of the conversation that built it.

---

## BLUF

narratr turns a document into a narrated video. A **Claude skill plus a local CLI**: Claude reads a doc and writes `scenes.json`, then a detached local process renders it.

**Everything planned is built and in use.** A run produces a frame-exact video with audio, captions and chapters. What remains is one design gap, not a defect.

Read [../research-plan.md](../research-plan.md) for the reasoning. This file carries state and next moves.

## Working agreement

**Confirm before implementing.** A described plan is not authorization. Ask, then build.

**Commit before starting a new piece of work.**

**Look at the artifact, not the exit code.** This has caught four separate faults that every structural check passed: a diagram rendered at 15% of frame width, a video whose audio was digital silence, Shiki HTML that was generated and then silently dropped, and progressive sync drift. **Follow his conventions without being told.** See `narratr-python-conventions` in memory; the repo is already in that shape.

**Writing style:** `~/obsidian-home/Claude Rules/Tonality.md` — BLUF, short sentences, no repetition, bullets as **topic** — detail. Mermaid must be `flowchart TD`; `LR` renders unreadably small in Obsidian.

## Decisions already closed — do not reopen

- **TTS is local Chatterbox Turbo.** ElevenLabs and Sarvam ruled out after a real listen.
- **The LLM is Claude in-session, via the skill.** Not the Messages API, not a `claude -p` subprocess.
- **Alignment is torchaudio, not WhisperX.** The text is known exactly, so transcription was never needed.
- **The voice is settled.** `assets/voices/sample-01.wav` is the project voice, approved on a real listen. It is Chatterbox-generated rather than a recording — provenance, not a defect. **Do not propose replacing it.**
- **Speed defaults to 0.92**, chosen by listening. The natural pace was too fast.
- **Cross-scene consistency: closed by judgement.** Six scenes sounded right; a 34-scene test was declined. Do not re-raise.
- **Work in short clips.** `examples/brief.scenes.json` (6 scenes, 74s) is the unit for iterating. Quote real-time factors, not extrapolations to hypothetical long videos.
- **Remotion, licence deferred.** Free below 4 people, headcount-based, internal use counts.
- **1080p30 stands.** Rendering is faster than realtime.

## Gotchas that cost real time

- **`setuptools<81` is load-bearing.** Chatterbox's watermarker imports `pkg_resources`, swallows the ImportError, and dies far away with `'NoneType' object is not callable`.
- **Release the MPS cache between scenes.** `narratr/device.py`. Without it the driver reserves 14.6 GB against 2.9 GB live, the machine swaps ~1M pages per generation, and rtf goes 1.0 → 4-6. **Any stage running a model on MPS needs it.**
- **Never encode audio per segment and then stream-copy.** Each AAC encode adds priming that its own edit list compensates for; `-c copy` cannot carry per-file edit lists, so the priming becomes real audio and the drift accumulates. Encode the whole timeline once.
- **Mute rendered video before concatenating.** Remotion writes a silent AAC track ~50 ms longer than its own picture, and concat advances by container duration.
- **`renderer_digest` must cover everything that shapes a frame.** Currently `render/remotion/src`, `mermaid.config.json`, `narratr/render.py` and `render/remotion/package.json`. Miss one and edits silently reuse cached video. **This has now bitten three times** — the palette change, an encoder flag, and the npm packages that draw the frames. If something new can change a pixel, it belongs in `RENDERER_SOURCES` before it is used, not after it fools you.
- **Do not match the Mermaid node *class*.** `Diagram.tsx` matches `g[id*="flowchart-<ID>-"]`, not `g.node[...]`. Mermaid writes `class="node default"` for a plain node and `class="icon-shape default"` for one carrying an icon, so the class-based selector stops matching the moment a diagram uses icons — and an unmatched node falls back to **visible**, so the diagram renders correctly and simply never animates. Every structural check passes it. The id pattern is the part that holds across both.
- **Mermaid caps its own SVG** with an inline `max-width`. Only `!important` beats it, and the container needs a definite box or `preserveAspectRatio` overflows.
- **Audio temp files must keep `.wav`.** torchaudio infers the container from the filename; `format="wav"` does not override it.
- **`torchaudio::forced_align` has no MPS kernel.** The emission moves to CPU explicitly. **Do not set `PYTORCH_ENABLE_MPS_FALLBACK`** — it hides costs.
- **Two scenes is not a benchmark.** The original rtf 1.59 came from the two scenes that run before memory pressure builds. Use six or more.
- **A slash in a run directory name silently nests it.** `mkdir` accepts it and creates two levels.

## Trade-offs taken in the presentation-language work

Recorded because each one is a fork someone will otherwise re-open from scratch.

- **The Mermaid node selector lost its class.** See the gotcha above. Taken as a
  defensive fix rather than to enable icons: a selector keyed on a class that
  Mermaid rewrites per shape was going to fail silently sooner or later. It is
  strictly *less* coupled to Mermaid internals than what it replaced.
- **Diagram icons proven, deliberately left off.** The decision was "the reveal
  animation matters more than icons in diagrams", taken before the selector
  question was settled. Both now work, so the premise is gone — see pending #2.
  Nothing in `narratr/`, `skill/` or `examples/` references icon packs for
  Mermaid; `mermaid_to_svg` calls `mmdc` with exactly the flags it always had.
- **Icons take `accent(i)`, the bar does not exist.** The rotation moved from
  the coloured bar onto the glyph rather than being dropped. A struck bullet
  overrides it: icon and text both go to `theme.dim` with a line through.
  Considered and rejected: one colour for the whole list.
- **An unknown icon name is a hard failure**, in `narratr validate`, with
  `difflib` near misses. A fallback to no icon would degrade one slide in a long
  video and be found on playback. Same reasoning as the coverage gate.
- **`bullets` accepts a string or an object.** Every spec written before this
  still validates. The object is `{text, icon?, state?, cue?}`.
- **`cue` is in the schema and does nothing yet.** Declared now because pending
  #1 wants the same field, and breaking the contract twice is worse than one
  unused key.
- **Two icon packs are installed and only one is used.** `lucide-static` (2,066
  names) feeds the components. `@iconify-json/lucide` (1,866 names) was pulled
  in for the Mermaid probe and is currently dead weight — and the count mismatch
  is a trap: a name valid in a bullet can be missing from the Mermaid pack. If
  diagram icons are taken up, generate the Iconify JSON from `lucide-static`
  instead and delete the second pack. If they are not, delete it now; either way
  it costs one full re-render because `package.json` is in the digest.
- **Flow tiles scale to step count** (2 → 248px, 5 → 160px). Fixed tiles left a
  two-step chain marooned in the middle of a 1920px frame.
- **`stitch._ffmpeg` and `render._run` are now public** as `stitch.ffmpeg` and
  `render.run_remotion`, because `intro.py` calls both and a leading underscore
  across a module boundary is a lie.

## What is pending, and how to do it

### 1. Cue reveals to speech — the one real gap

**Why:** bullets appear on an even schedule across 60% of the scene with no
reference to when their words are spoken. Measured drift between reveal and
speech ran −3.0s to +2.0s, with 11 of 13 matched elements more than a second
out. Nothing is broken; the videos would simply be markedly better.

**How, and what not to try:** do **not** infer the cue by matching bullet text
against the narration afterwards. Bullets are paraphrases — "Narrated video out"
never appears in a script that says "turns a document into a narrated video" —
and a matcher found nothing usable for 5 of 18 elements.

Have Claude emit the cue instead, since it writes both sides:

- **Schema** — `bullets` accepts `{text, cue}` as well as plain strings, where
  `cue` is a short verbatim phrase from that scene's narration.
- **`skill/SKILL.md`** — instruct that each bullet carries its trigger phrase.
- **Renderer** — resolve cues against `store/timings/` and pass resolved times
  as a prop; `beatAt` stays as the fallback when a cue is absent or unfound.
- **`narratr sync`** — promote the throwaway diagnostic to a real command so
  drift is measurable rather than felt.

### 2. Icons inside Mermaid diagrams — proven, deliberately not wired up

**State:** verified working. `mermaid-cli` 11.17.0 renders
`A@{ icon: "lucide:file-text", form: "square", label: "Document" }` with the
text label intact, and the reveal selectors survive now that the node class is
no longer matched.

**Why it is off:** it was left out on the decision that the reveal animation
matters more than icons in diagrams, taken before the selector question was
settled. Both work now, so that premise is gone. This is a choice to revisit,
not a blocker.

**Whether it is worth it:** narrower than it looks. `flow` already does the
icon-plus-label sequence better — bigger glyphs, staged reveal, no layout engine
in between. What diagram icons buy is *structural* pictures: branches, clusters,
eight nodes where `flow` does not apply.

#### The obstacle, in one line

`mermaid.registerIconPacks` takes a **loader function** and would accept
`() => pack`. `mermaid-cli` hardcodes that loader to `fetch(url)`
(`src/index.js:514-538`), so the pack has to arrive as a URL rather than as
data. Every option below is a different answer to "whose page is it?"

#### The route to take

Keep `mermaid-cli`, give it a URL that resolves locally, and fix the two things
that would otherwise make that fragile:

1. **One pack, generated, not two.** Iconify's format is
   `{prefix, icons: {name: {body}}, width, height}` where `body` is the inner
   SVG wrapped in a `<g>` carrying the stroke attributes — mechanically
   derivable from the `lucide-static` files `narratr/icons.py` already reads.
   Generate it, content-address it into `store/`, delete
   `@iconify-json/lucide`. This is not tidiness: the two packs have different
   name sets (2,066 vs 1,866), so keeping both means a name that validates in a
   bullet can be missing in a diagram, invisibly.
2. **Assert the glyph landed.** `mermaid-cli` catches a failed pack load and
   carries on, so the diagram renders, validates and silently has no icons.
   `mermaid_to_svg` must check the output SVG contains the icon body and raise
   otherwise. This is the check that makes the whole thing safe — same
   discipline as `check_audible`.
3. **Serve it properly.** Bind `127.0.0.1` on **port 0** so the OS assigns it
   and there is no magic number to collide with; serve one in-memory document;
   live only for the duration of the `mmdc` subprocess. **The response needs
   `Access-Control-Allow-Origin: *`** — the rendering page's origin is `null`,
   and without the header the fetch is blocked by CORS and the icons vanish
   silently. That cost an hour to find.
4. **Validate the names.** Mermaid icons live inside the `mermaid` string, so
   `icons.names_in` cannot see them. Extract `lucide:<name>` from the source or
   diagram icons become the one place a typo escapes the gate.
5. **`skill/SKILL.md`** — icons on nodes that name a *thing*, not a step;
   `flow` stays the answer for a plain sequence.

About 80 lines and tests.

#### The alternative, and when to take it

Replace `mermaid-cli` with our own puppeteer harness. Then the loader closes
over the parsed JSON, no fetch happens at all, and the API is used as designed —
and a dependency that drags in Font Awesome and a second Chromium goes away.
The cost is that `mermaid-cli` does more than it looks: font loading and
`document.fonts.ready`, external diagram registration, layout loaders,
background handling. Roughly 200+ lines we then own across every Mermaid bump,
with a risk of subtly different SVGs from the ones already cached.

**The trigger:** fighting `mermaid-cli` a second time. One workaround for one
limitation is fine. Two means the dependency is not paying for itself.

### 3. Run a long document

**Why:** 51 blocks worked. Nothing longer has been tried, and the coverage
ledger is the part most likely to strain.

**How:** point the skill at a longer document, watch whether Pass 1 maps
everything and Pass 2 stays coherent. Render a subset with `--only` rather than
the whole thing.

- **Does the Mermaid selector matching survive a version bump?** `Diagram.tsx`
  now matches `g[id*="flowchart-<ID>-"]` and `path[data-id^="L_<from>_<to>_"]`.
  The node *class* was dropped from the selector deliberately: Mermaid writes
  `node default` for a plain node and `icon-shape default` for one carrying an
  icon, so `g.node` stopped animating the moment a diagram used icons. Unknown
  ids still fall back to visible, so a structural change degrades to a static
  diagram rather than a blank frame — and does so silently. Pin the mermaid
  version.

  costing nothing.
