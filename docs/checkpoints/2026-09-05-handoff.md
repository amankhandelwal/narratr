## Decisions already closed — do not reopen

- **TTS is local Chatterbox Turbo.** ElevenLabs and Sarvam were evaluated and ruled out after a real listen. Cost bought nothing that could not be replaced locally.
- **The LLM is Claude in-session, via the skill.** Not the Messages API (needs separately purchased credits), and not a `claude -p` subprocess (an earlier design, abandoned because running in-session removes auth, ambient-config pinning, and the `--bare` risk entirely).
- **Remotion, licence deferred.** Aman chose the fastest path to a working pipeline, accepting that a later swap means rewriting scene components. See the risk below.
- **`make setup` is incremental; `make reset` is the destructive rebuild.** A rebuild costs a 1.1 GB reinstall, so it is opt-in.

## Gotchas that cost real time

- **`setuptools<81` is load-bearing.** Chatterbox's watermarker imports `pkg_resources`, swallows the ImportError, and dies far away with `TypeError: 'NoneType' object is not callable`. The pin is in `pyproject.toml` with a comment. Never "tidy" it.
- **Atomic writes for audio must keep the `.wav` extension.** torchaudio infers the container from the filename, so a `.tmp` suffix fails with `Unsupported format: tmp`. The pattern is `out.with_name(f".{out.name}.partial.wav")` then `rename()`. Passing `format="wav"` does **not** fix it — the soundfile backend still reads the path.
- **Never hand-roll venv handling.** An earlier `bin/narratr` re-exec'd into `.venv/bin/python` by comparing resolved paths; that venv python is a symlink to the same pyenv binary, so the check always passed and the CLI silently ran on system `sys.path`. `uv run` plus `[project.scripts]` removes the whole class.
- **MPS timings are erratic.** Turbo has ranged rtf 1.25–5.61 per scene. Do not treat a single measurement as signal.

## ⚠️ The reference voice is fake

`assets/voices/sample-01.wav` is **Chatterbox output, not a human recording** — it was produced during benchmarking and reused as a stand-in. Any voice cloned from it is a copy of a copy and says nothing about real quality.

**Before judging output quality, record ten clean seconds of a real voice** and point `voice.reference` at it.

## What to do next, in order

### 1. Exercise the skill on a real document

Never done. The whole coverage-ledger design is untested against real input.

Point a Claude session at `docs/research-plan.md` itself, run the skill, and see whether Pass 1 maps every block and Pass 2 writes narration worth listening to. Fix `skill/SKILL.md` based on what actually goes wrong.

**This is first because it validates the part that cannot be unit-tested.**

### 2. Test cross-scene voice consistency

The open quality risk. Longest run so far is three scenes.

Take the `scenes.json` from step 1, render ~20 scenes, listen straight through. Does scene 20 still sound like scene 3? If it drifts, that undermines the TTS choice and needs solving before anything downstream is built.

### 3. Build alignment

Smallest remaining stage. Implement `narratr/stages.py::align`:

- Add `whisperx` to `pyproject.toml` dependencies, run `uv sync`
- Input: `runs/<id>/audio/*.wav`, already on disk
- Output: word timings into the manifest, plus `runs/<id>/captions.srt`
- Content-address and checkpoint it the same way narration is — reuse `Manifest.mark(scene_id, "aligned", ...)`
- Useful: `~/.cache/huggingface` already holds `faster-whisper-large-v3-turbo`

### 4. Benchmark Remotion before writing any scene components

```sh
npx remotion benchmark
```

Two things get decided here, and both get more expensive later:

- **Performance.** If a 36-minute render is far worse than 30–60 minutes, drop to 24fps and 1600×900 before changing anything architectural.
- **The licence.** Remotion needs a paid Company License above 3 people, counted by headcount, internal use included — so using narratr on a work laptop triggers it. Free use needs no account or key; this is a terms obligation, not an enforced one. If it has to change, Motion Canvas (MIT) is the swap target and `render/CONTRACT.md` is what keeps that from being a rewrite. **Every scene component written raises the cost of that swap.**

### 5. Build the renderer

Implement `narratr/stages.py::render` against `render/CONTRACT.md`. It receives one scene plus its measured audio duration and writes one mp4. It must not read `scenes.json`, know about TTS, or depend on scene order.

Diagram scenes: Mermaid → SVG, then interpolate opacity per `revealSteps` group across the duration. Pin the Mermaid version and snapshot-test the selectors — node ids and class names are not a public API.

### 6. Stitch

FFmpeg `concat` demuxer with stream copy. Add chapter markers, since a 36-minute video needs them.
